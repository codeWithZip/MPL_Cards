# 💳 Учёт платежей — Терминал

**Локальная платформа для учёта поступлений по банкам, картам и СБП-реквизитам.** Работает на Windows через браузер, без облачного сервиса и отдельной SQL-базы. Данные сохраняются в JSON-файлах на компьютере.

> **Версия интерфейса:** v24. Скриншоты ниже сделаны с **вымышленными демонстрационными данными** — не с реальными платежами или реквизитами.

![Главная страница платформы](screenshots/01-overview.png)

## Возможности

- **Автоматический импорт:** вставьте текст транзакции с сайта через `Ctrl + V` в поле «Быстрый импорт» или нажмите «Из буфера»; новые распознанные платежи добавляются автоматически.
- **Защита от дублей:** проверка по ID транзакции, предупреждения о повторах и ошибках.
- **Учёт по банкам и реквизитам:** суммы, количество оплат, группировка по датам и сортировка внутри банков.
- **Удобные номера:** карты отображаются группами по четыре цифры, телефоны — с пробелами, рядом значок карты или СБП.
- **Справочник карт:** собственные названия, поиск, просмотр сумм поступлений и последнего платежа.
- **Поиск:** банк, получатель, ID транзакции, номер заказа, последние 4 цифры карты или телефона.
- **Статистика:** общая сумма, количество операций, уникальные реквизиты, банки и расчёт **8% / 9%** от принятых сумм.
- **Отмена удаления:** восстановление последнего удалённого платежа.
- **Локальное хранение:** `database.json` и `cards.json` рядом с приложением, резервные копии при записи в папке `backups/`.

## Установка на Windows

1. Установите **Python 3** с [python.org](https://www.python.org/downloads/windows/) и разрешите добавление Python в `PATH` (если установщик предлагает).
2. Скачайте или клонируйте репозиторий. При скачивании с GitHub выберите **Code → Download ZIP** и распакуйте файлы в папку, где разрешена запись.
3. Дважды нажмите **`START.bat`**.
4. В браузере откройте **http://127.0.0.1:8765**. Пока пользуетесь платформой, не закрывайте окно сервера.

Проверка Python через CMD:

```bat
python --version
```

Если `python` не распознаётся, попробуйте `py -3 --version` и при необходимости скорректируйте `START.bat`.

**Важно:** открывайте приложение через `START.bat`, **не** запускайте `index.html` двойным щелчком — без локального сервера сохранение в JSON не работает.

## Как пользоваться

### 1. Добавить платёж вручную

В **левой колонке** заполните сумму, дату, банк, карту/телефон, получателя и ID транзакции. Нажмите **«Сохранить платёж»**. Для новых операций статус фиксирован как «Оплачен».

### 2. Импортировать транзакцию из текста

В **правой колонке** вставьте скопированный блок с сайта в поле **«Быстрый импорт»** через `Ctrl + V` либо нажмите **«Из буфера»**. Программа распознает сумму, получателя, реквизиты, банк, ID и номер заказа, проверит повторения и сохранит новые корректные операции. Если что-то не распозналось, появится сообщение с причиной.

![Быстрый импорт](screenshots/05-import.png)

### 3. Посмотреть итоги по банкам

В **центральной колонке** выберите вкладку **«По банкам»**. Банки изначально свёрнуты: видны общая сумма и количество оплат. Нажмите на нужный банк, чтобы увидеть его карты, телефоны и распределение поступлений.

![Банки свёрнуты](screenshots/02-banks-collapsed.png)

![Детали банка](screenshots/03-bank-details.png)

### 4. Присвоить карте имя

Нажмите **«Справочник карт и названий»** в левой колонке. В модальном окне можно найти реквизиты по банку, номеру или собственному названию и задать имя, например **«Инго · основная»**. Названия сохраняются в `cards.json`.

![Справочник карт](screenshots/04-card-directory.png)

### 5. Найти операцию

Используйте строку поиска над таблицей: подходит название банка, сумма, получатель, ID, номер заказа и **последние четыре цифры** реквизита. Можно применять фильтры по дате и банку.

### 6. Посмотреть заработок

В шапке два показателя — **8%** и **9%** от общей принятой суммы с учётом выбранных фильтров. Это *два альтернативных расчёта*, а не суммарный заработок.

## Файлы проекта

```text
├── START.bat              # запуск на Windows
├── server.py              # локальный HTTP-сервер и работа с JSON
├── index.html             # интерфейс приложения
├── database.json          # ваши платежи (создаётся/заполняется локально)
├── cards.json             # ваши названия карт (создаётся/заполняется локально)
├── backups/               # автоматические локальные копии (после записей)
├── screenshots/           # демонстрационные изображения для README
├── database.example.json  # пример пустой базы
└── cards.example.json     # пример пустого справочника
```

При первом запуске пустые `database.json` и `cards.json` можно создать с содержимым `[]` либо скопировать из соответствующих файлов `.example.json`.

## Перенос данных при обновлении

1. Закройте сервер предыдущей версии.
2. Сохраните копии **`database.json` и `cards.json`** в безопасном месте.
3. Распакуйте новую версию.
4. Перенесите оба JSON-файла в папку новой версии.
5. Запустите `START.bat` и при необходимости обновите вкладку `Ctrl + F5`.

## Частые проблемы

| Проблема | Что проверить |
|---|---|
| `Python 3 is required` | Установите Python 3, проверьте `python --version` и `PATH`. |
| Страница не открывается | Запущен ли `START.bat`, доступен ли адрес `127.0.0.1:8765`? |
| Не сохраняет платежи | Запускайте через сервер, проверьте права записи в папку и свободное место. |
| «Платёж уже существует» | Операция с таким ID уже есть в базе: проверьте её поиском. |
| Не распозналась строка | Убедитесь, что в тексте есть сумма в RUB и строка с реквизитами и банком. |
| Не удаётся открыть буфер | Вставьте через `Ctrl + V` прямо в поле импорта. |

## Приватность и публикация на GitHub

**Не публикуйте реальные `database.json`, `cards.json` и `backups/`!** В них могут находиться персональные данные, реквизиты и история платежей. В комплект включён `.gitignore`, исключающий эти файлы; примеры пустых JSON доступны как `.example.json`. Перед публикацией всё равно проверьте список файлов командой `git status` и убедитесь, что данные ранее не попали в историю Git.

Сервер слушает только локальный адрес **127.0.0.1**; платформа не предназначена для открытого размещения в интернете без отдельной переработки защиты и авторизации. **GitHub Pages не запустит `server.py`** — для работы требуется локальный Python-сервер.
